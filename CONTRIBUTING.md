# Руководство для контрибьюторов

Спасибо за интерес к развитию Базы знаний ShotSCOPE! Это живой организм, и каждый ваш вклад делает его полезнее.

## 🔍 С чего начать?

1.  **Исследуйте:** Посмотрите существующие [Issues](ссылка на issues), возможно, ваша проблема или идея уже обсуждается.
2.  **Обсудите:** Если тема новая, создайте Issue. Мы сможем подсказать, в какой раздел лучше поместить материал и не дублирует ли он существующий.
3.  **Ветвитесь:** Мы используем простую модель. Основная ветка — `v4` (как требует Quartz). Все изменения вносятся через форки и Pull Request.

## ✍️ Процесс внесения изменений

1.  **Форкните** репозиторий.
2.  **Клонируйте** свой форк локально.
3.  **Настройте Obsidian:**
    *   Откройте клонированную папку как хранилище (Vault) в Obsidian.
    *   Убедитесь, что у вас включены настройки, описанные в [`OBSIDIAN_SETTINGS.md`](OBSIDIAN_SETTINGS.md) (особенно касающиеся wikilinks и папок).
4.  **Внесите изменения:**
    *   Следуйте правилам из [`STYLE_AND_TEMPLATES.md`](STYLE_AND_TEMPLATES.md).
    *   Для новых статей используйте соответствующий шаблон.
    *   Убедитесь, что все внутренние ссылки (`[[относительная ссылка]]`) ведут туда, куда нужно.
5.  **Проверьте:**
    *   Убедитесь, что файл открывается в Obsidian без ошибок.
    *   Проверьте, как будет выглядеть будущая страница, используя локальный сервер Quartz (если есть возможность) или просто визуально оценив Markdown-разметку.
6.  **Закоммитьте и запушьте** в свой форк.
7.  **Откройте Pull Request** в наш репозиторий, используя [шаблон](.github/PULL_REQUEST_TEMPLATE.md).

## 📝 Правила именования коммитов

Мы используем **[Conventional Commits](https://www.conventionalcommits.org/ru/v1.0.0/)**. Это помогает автоматически генерировать список изменений и понимать суть коммита без просмотра кода.

### Структура коммита

```
<тип>[необязательный область]: <описание>

[необязательное тело]

[необязательный нижний колонтитул]
```

### Основные типы для нашей базы знаний

| Тип | Когда использовать | Пример |
|-----|-------------------|--------|
| `feat` | Добавление новой статьи | `feat(shotscope): инструкция по звуковому тренажеру` |
| `fix` | Исправление ошибки (опечатка, битая ссылка) | `fix(rules): обновлена ссылка на правила IPSC` |
| `docs` | Изменение документации (README, гайды) | `docs: обновлен CONTRIBUTING.md` |
| `style` | Исправление форматирования (пробелы, заголовки) | `style: приведены заголовки к единому виду` |
| `refactor` | Переструктурирование контента без изменения смысла | `refactor: перемещение статьи в другую папку` |
| `chore` | Обслуживание репозитория (настройки, шаблоны) | `chore: обновлен шаблон PR` |

### Рекомендации

*   Описание должно быть кратким (до 72 символов), детали — в теле коммита

### Примеры хороших коммитов

```bash
git commit -m "feat(antidoping): добавлен список запрещенных веществ на 2024"
git commit -m "fix(weapons): исправлена опечатка в названии калибра"
git commit -m "docs: обновлена ссылка на лицензию в README"
git commit -m "refactor: перемещение статьи из Athletes в Coaches"
```

## 🔀 Правила именования Pull Request

Название PR должно следовать той же конвенции, что и коммиты. Это позволяет автоматически связывать PR с релизами.

**Формат:** `[тип(область)] Краткое описание`

**Примеры:**

- `feat(shotscope) Инструкция по звуковому тренажеру`
- `fix(rules) Обновление ссылок на правила`
- `docs Обновление руководства для контрибьюторов`

## ©️ Авторские права и атрибуция

Мы хотим, чтобы авторы получали признание за свой труд.

*   **Ваше авторство:** Если вы создаете новую страницу или вносите значительный вклад в существующую, вы имеете полное право указать свое авторство. Добавьте в конец статьи блок:
    `--- *Автор: [Ваше имя или псевдоним]*`
*   **Согласие на публикацию:** Отправляя Pull Request, вы автоматически соглашаетесь на то, что ваш текст будет опубликован на сайте wiki.shotscope.ru и может распространяться сообществом на условиях лицензии [CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/deed.ru). Это означает, что другие люди могут делиться и адаптировать материал, но с обязательным указанием авторства (вашего!) и на тех же условиях.
*   **Коллективная работа:** Если вы редактируете чужую статью, пожалуйста, не удаляйте блок авторства оригинального создателя без крайней необходимости. Лучше добавить примечание о дополнительном вкладе.

## ✅ Что проверяется в PR?

*   **Актуальность:** Соответствует ли информация последней версии приложения/правил.
*   **Грамотность:** Нет ли грубых орфографических ошибок.
*   **Структура:** Правильно ли проставлены заголовки, списки, ссылки.
*   **Уникальность:** Не копирует ли статья существующий материал без необходимости.
*   **Стиль:** Соответствует ли текст [стайлгайду](STYLE_GUIDE.md)
*   **Коммиты и PR:** Соблюдение договоренностей по неймингу коммитов и PR

Еще раз спасибо, что вы с нами! 🚀
